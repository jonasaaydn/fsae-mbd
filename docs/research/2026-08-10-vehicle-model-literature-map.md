## 第33章 セットアップ感度解析

**扱う階層**: 大域サンプリング（ラテン超方格 / Sobol 列）＋標準化回帰係数 / Sobol 指数。**目的関数を「ラップタイム」から「得点」へ引き上げる**層まで。

**扱わない**: モデル構築そのもの（第23・29・31・32章）、パラメータの不確かさ推定（第25・27章）。

**本文の骨子**
- **OAT（一因子ずつ）の限界を最初に潰す**：ロール剛性配分と空力バランスのように交互作用の強いパラメータでは、トルネード図は最適点を見落とす。
- サンプリング：`lhsdesign` / `sobolset`（Statistics and Machine Learning Toolbox）、または Simulink Design Optimization の Sensitivity Analyzer（`sdo.sample` / `sdo.evaluate` / `sdo.analyze`、Method は `'latinHypercube'` / `'sobol'` 等）。
- **サンプル数 × 計算時間の制約から、この目的では過渡モデルではなく QSS を使う**という判断を明示的に教える。
- **得点最適化への引き上げ**：得点式は非線形（オートクロス・エンデュランスは `Tmax/Tteam` の比の形、効率は `EF = T²·E`）。同じ 0.1 秒でも順位によって得点への寄与が違う。配点は大会ごとに異なる（本調査で確認した FSG 2025 CV/EV：Business 75 / Cost 100 / Design 150 / Skidpad 50 / DV Skidpad 75 / Acceleration 50 / DV Acceleration 75 / Autocross 100 / Endurance 250 / Efficiency 75 ＝ 合計 1000。静的 325 ＋ 動的 675 で検算一致）。**FSAE US・JSAE は配点が異なるので、読者は自分の大会の当該年度規則を確認する。**
- **効率スコアを無視したラップタイム最適化は 75 点に一切答えられない**。QSS に燃料流量モデル（第21章の BSFC）を足すのは比較的容易で費用対効果が高い。

**限界と適用範囲節に書くこと**
- **問いたい機構がモデルに入っていなければ、感度は常にゼロになる。** 「影響が無い」と「モデルに無い」を混同しない（第29章の点質量の件）。
- パラメータの不確かさ（第25章）を入れずに感度だけ見ると、「効くが測れていない」パラメータを見落とす。**感度 × 不確かさ**で優先順位をつける。
- 第32章の Lagrange 乗数から得た感度は、その最適解の近傍でしか有効でない。

## 第34章 センサと可観測性

**扱う階層**: 線形可観測性（`obsv(A,C)` のランク、PBH）、非線形の局所弱可観測性（リー微分）、拡大系と持続的励振、レバーアーム補正・時刻同期・レイテンシ。

**扱わない**: 推定器そのもの（第35章）、制御（第36章以降）。

**本文の骨子**
- **第V部の冒頭で「降りる」ことを宣言する**：ここから必要なのは高忠実度モデルではなく、**低次で可観測・実時間で解ける設計モデル**。第I部の線形2輪モデルが現役に戻る。
- `obsv` のランクチェックは数行で書けるので、**コストゼロで「そのセンサ構成では原理的に無理」を証明できる**。FSAE で限られたセンサ予算をどこに使うかを決める唯一の合理的根拠。
- **センサ予算の3階層**（本書で最も実務的な判断軸）：
 (a) 最小（車載 MEMS 6軸 IMU ＋ 舵角ポテンショ）→ 運動学的積分のみ。ドリフトを見て終わる。
 (b) 中位（4輪ホール輪速 ＋ IMU ＋ 単独 GNSS）→ 相補フィルタ・EKF が成立。**FSAE で最も費用対効果が良い到達点。**
 (c) 上位（2アンテナ RTK-GNSS または光学式対地速度計）→ `β` の真値が得られ、**初めて下位階層の推定器を検証できる。**
- **重要な含意**：推定精度を上げるセンサより先に、**検証を可能にするセンサ**を買うべき場面が多い。

**限界と適用範囲節に書くこと**
- 定常円旋回のように入力が一定だと拡大系の可観測性が失われ、**`β` の誤差と `Cα` の誤差が原理的に区別できない**（持続的励振の不足）。
- 横加速度計を足しても、ロール角／バンク角による重力成分 `g·sinφ` と真の横加速度が分離できないため可観測性は回復しない。
- **「可観測でない」と判明したときの正しい対処は、推定器を高度化することではなく、(a) 独立したセンサを足す か (b) モデルを縮約する のどちらか。**
- 学術論文の大半は量産 ESC 搭載車（ヨーレートセンサ・4輪 ABS 輪速・舵角センサが標準装備、車両パラメータ既知）を前提にしている。FSAE 車は輪速すら付いていないことがある。**「論文どおりに作ったのに動かない」の大半はここ。**

## 第35章 拡張カルマンフィルタによる車体すべり角推定

**扱う階層**: 運動学的積分 → モデルベース開ループ → ルーエンベルガ観測器 → **相補的融合（FSAE の主力）** → EKF → UKF → GNSS/INS 統合。この6段を1章で登り切る。

**扱わない**: 制御則（第36章以降）、非線形観測器 SMO/MHE（位置づけのみ）、学習ベース（位置づけのみ）。

**本文の骨子**
- **登り方をそのまま章構成にする**：
 1. 運動学的積分 `β̇ = a_y/v_x − r` を10行で実装し、**ドリフトを自分の目で見る**。これが以降の全階層の動機づけ。
 2. 線形2輪モデルによる開ループ推定（ドリフトしないがモデル誤差がそのまま乗る）。
 3. 2つの誤差が周波数的に相補的であることを示し、**相補フィルタで融合**。**EKF のチューニングに何ヶ月も苦しむより、まずここを実車で成立させる。**
 4. 重みを共分散から自動決定するものとして EKF を導入（＝カルマンの最も自然な動機づけ）。
 5. UKF は「EKF を実測で検証し、飽和域で明確に劣化していることを確認してから」。
 6. GNSS/INS は「検証を可能にする投資」として位置づける。
- **低速の特異点対策**：`α = atan(v_y/v_x)` は `v_x → 0` で定義不能。AMZ Driverless は `v_x ∈ [3, 5] m/s` でキネマティックモデルとダイナミックモデルを線形ブレンドしている。**単に「低速では推定を止める」と、止めた瞬間に状態が飛ぶ。**

**限界と適用範囲節に書くこと**
- **EKF の本質的な弱点**：タイヤ飽和域では `∂Fy/∂α ≈ 0` になり1次線形化が破綻する。つまり**限界域こそ `β` の推定が必要なのに、限界域で最も精度が落ちる**。この非対称性を明記する。
- **`Q` を大きくして安定させる、は逃げ**。`Q` を大きくすることはモデルを信じないことであり、極端に振ると実質的に運動学的積分に戻る。「EKF を組んだのに挙動が積分と同じ」という失敗は極めて多い。**`Q` と `R` には物理的根拠（データシートのノイズ密度、モデル誤差の実測分散）を持たせる。**
- バンク角／ロール角による `g·sinφ` の混入（ロール 2° で約 0.34 m/s²）。ロール角を推定するか、無視できる根拠を数字で示すか、どちらか。
- 輪速を車体速度の代用にしない（高加速時に最大30%程度のスリップ、強制動ではさらに大きい）。
- **GNSS は 100〜200 ms 遅れる**。遅延補正なしに「現在時刻の状態」に対して更新をかけると推定が発振する。遅延補正は追加機能ではなく必須要件。
- **検証用の真値がないまま上位階層に進まない**。「推定器を作った」と「推定器が正しい」は別問題。
- `σ`（緩和長、第7章）を入れない推定器は、ステア入力直後に系統的バイアスを出す。

## 第36章 PIDの限界

**扱う階層**: フィードフォワード（マップ）→ PID（anti-windup 必須）→ ゲインスケジューリング。

**扱わない**: 状態フィードバック（第37章）、制約付き最適化（第39章）。

**本文の骨子**
- **順序を守る**：フィードバックを足す前に FF をきちんと作る。FF が悪いままフィードバックゲインを上げるとアクチュエータが飽和して破綻する。多くの FSAE 車が FF 層にいるのは悪いことではない。
- ゲインスケジューリング：`tunableSurface` でゲイン面をパラメータ化 → `systune` で全設計点を同時に満たすよう一括チューニング → `slTuner` で Simulink に紐付け → ルックアップテーブル化してコード生成。
- FSAE の速度域（20〜100 km/h 程度）でも横方向動特性は明確に変わる（第4章の定常ヨーレートゲイン、第5章の `ω_n` が車速依存）。**第I部の結果がそのままこの章の警告の根拠になる。**

**限界と適用範囲節に書くこと**
- PID は SISO なので MIMO 干渉を扱えない（舵角もブレーキも駆動トルクも全部ヨーに効くのに1対1しか見ない）。
- **制約（タイヤの摩擦円）を知らないので、物理的に不可能な指令を出し続ける。**
- **anti-windup はオプションではなく必須。**
- ゲインスケジューリングの罠：**各動作点で安定なコントローラを補間しても、補間された系の安定性は保証されない。** 設計点の間で不安定になりうる。スケジューリング変数が速く変化すると（急加速・急制動・スピン）保証が消える。
- 進むべき条件：干渉と制約が問題なら第37・39章へ。遷移が速い／設計点数が増えすぎたら線形時変 MPC や LPV へ。

## 第37章 状態フィードバックとLQR

**扱う階層**: 状態フィードバック、LQR / LQI / LQG、重み設計（Bryson 則）、分離定理。

**扱わない**: 制約付き最適化（第39章）、SMC（位置づけのみ）。

**本文の骨子**
- 設計例：ヨーレート追従と `β` 抑制を同時に扱う。状態に `β` が含まれるため、**第35章の推定器（相補フィルタ以上）が前提**。本書が推定と制御を同じ部で扱う理由がここにある——**制御は推定より良くならない。**
- 重み `Q, R` は Bryson 則（各状態・各入力の許容最大値の2乗の逆数）から始める。**「なんとなく大きくした」で得たゲインは設計意図を後から説明できない。**

**限界と適用範囲節に書くこと**
- **LQR は制約を扱えない。しかし限界走行とは定義上「タイヤの摩擦円という制約の上にいる」状態である。したがって限界域では LQR は最適ではない。これが第39章へ進む本質的な理由**であり、逆に**限界に当たらない領域では MPC の利点はほとんど出ない**。
- **LQR のロバスト性（位相余裕 60°・ゲイン余裕無限大）は状態が全部測れる場合の話**。カルマンフィルタと組んだ LQG ではこの保証は失われる（Doyle の有名な結果）。「LQR は頑健」と覚えて LQG に持ち込むのは誤り。
- 線形モデルが有効な範囲でしか成立しない（第3章の `a_y ≲ 0.3–0.4 g`）。ゲインスケジューリング（第36章）と組むのが現実解。

## 第38章 トラクションコントロール

**扱う階層**: **7自由度モデル（車体3＋車輪回転4）**、スリップ率制御、μ-λ 曲線とその不安定領域、ICE のアクチュエータ選定、ESC 構造（参照ヨーレート＋摩擦上限クリップ）の位置づけ。

**扱わない**: MPC 化（第39章）、実装（第40〜43章）、実車評価（第47章）。

**本文の骨子**
- 7自由度への拡張：`J·ω̇ = T_drive − T_brake − Fx·R_e`。スリップ率 `κ` が動的な状態量になり、ホイールロック・ホイールスピンが陽に表現できる。
- **ICE のアクチュエータ選定が制御性能を決める**：スロットルは吸気系の輸送遅れで遅い。**点火リタード・燃料カットは桁違いに速い。** これが「離散ダイナミクスのアクチュエータ」の議論に直結する。
- **ICE FSAE で実行可能なヨー／トラクション制御は3つに限られる**と明記する：(1) スロットル／点火リタード／燃料カットによる TC、(2) LSD のランプ角・プリロードによるパッシブなヨーモーメント配分（第22章）、(3) 左右独立に圧力を作れる油圧系があればブレーキベースのヨー制御（実装例が少なくハードウェア追加が前提）。
- **電動トルクベクタリング文献の適用限界を明記する**。4輪独立電動駆動前提の論文をそのまま引用すると、実現不可能な設計を学生に書かせることになる。

**限界と適用範囲節に書くこと**
- **`λ` の分母は車体速度であり、その推定精度がそのまま TC の性能上限になる**。第38章は第35章に依存する、と明示する。
- **μ-λ 曲線のピーク右側は `∂μ/∂λ < 0` の不安定領域**。制御が遅い／推定が悪いと発散的にホイールスピン（またはロック）する。固定目標 `λ` は路面・タイヤ温度でピークが動くので最適にならない。
- **ABS は FSAE では実質不可**：FS Rules 2026 T 6.1 が manual mode での brake-by-wire を禁止。加えてスリップ率は直接測れず、4輪同時ロック時には車速推定の基準が消える。**MathWorks 自身が `sldemo_absbrake` について「実車では非現実的」と明記している**——「モデルをいつ信じてはいけないか」の格好の教材。
- ESC の**参照ヨーレートを摩擦上限（概ね `r_max ≈ μ·g/v_x`）でクリップしない**と、低 μ 路で物理的に不可能な目標を出し、制御が飽和して逆に不安定化する。実装で最も多い事故。
- ロックアップ後（`κ → −1`）は MF の外挿域。ロック中の挙動を論じる用途には使ってはならない。
- 数値剛性：ホイール慣性 `J` が小さくスリップ剛性が高いと固定ステップソルバで発散する → 第40章に直結。

**参照文献**
- Enomoto, H., et al., "Development of the Traction Control System with the Custom Electrical Control Unit for the Formula SAE Car," SAE 2007-32-0119, 2007 — https://doi.org/10.4271/2007-32-0119（有料・SAE Mobilus。**FSAE 実装事例**）

## 第39章 モデル予測制御（MPC）

**扱う階層**: 線形 MPC → 線形時変／適応 MPC → 非線形 MPC → MPCC（Model Predictive Contouring Control）。

**扱わない**: 学習ベース制御（位置づけのみ、実行不可と明記）、実装（第40〜43章）。

**本文の骨子**
- **導入は第37章から連続させる**：LQR が扱えなかった制約を陽に扱う枠組みとして MPC を導入する。
- FS Driverless での具体的な実装値（AMZ Driverless）：ソルバ ForcesPro NLP、サンプリング 50 ms、予測ホライズン `N = 40`（＝2秒先読み）、タイヤ摩擦楕円を制約として陽に記述、`β_dyn` と `β_kin` の差にコストを掛けて挙動の攻撃性を調整。
- 低速の特異点対策（第35章と同じ）：`v_x ∈ [3, 5] m/s` でキネマティックとダイナミックを線形ブレンド。
- 実装：Model Predictive Control Toolbox の `nlmpc` / Nonlinear MPC Controller ブロック。**`validateFcns` で予測モデルの整合性を事前検証（必須）**、`convertToMPC` で線形化して高速化、`nlmpcmoveCodeGeneration` ＋ Embedded Coder。

**限界と適用範囲節に書くこと**
- **モデルが間違っていれば MPC は自信を持って間違える。** しかも予測ホライズン全体でモデル誤差が積算するので、**同じモデル誤差でも PID より結果が悪くなりうる**。MPC の前提は「良いモデル」であり、モデルが良くないなら MPC に進む段階ではない。
- **実行不可能（infeasible）時のフォールバックを設計しないと実車で制御が無反応になる。** トラック制約・状態制約はスラック変数で軟化するのが定石。ハード制約だけで組むのは危険。
- **計算時間は平均でなく最悪ケースで評価する。** 平均 10 ms でも最悪 80 ms なら 50 ms 周期は破綻する（第40・43章で最悪実行時間の計測を要求する）。
- **制御周期を速くすればレイテンシ問題が解決すると思わない。** 支配的なのはセンサ→推定→制御→アクチュエータの総遅れ。AMZ Driverless はコーン検出から制御指令到達まで約 300 ms の遅延があり、これが原因で最高速とホイールトルクを制限せざるを得ず人間ドライバの性能に届かないと明記している。**世界トップの学生チームですらこれが最大のボトルネック。**
- **有人 FSAE での使いどころは薄い**（ドライバがすでに閉ループを構成している）。介入は「ドライバが違和感を持たない」範囲でしか使えず、ラップタイムへの寄与は自明でない。**シミュレーションだけで効果を主張してはいけない**（第44〜48章での評価が必須）。

**参照文献**
- Falcone, P., Borrelli, F., Asgari, J., Tseng, H. E., Hrovat, D., "Predictive Active Steering Control for Autonomous Vehicle Systems," IEEE TCST 15(3), pp. 566–580, 2007 — https://doi.org/10.1109/TCST.2007.894653（有料・IEEE）
- Liniger, A., Domahidi, A., Morari, M., "Optimization-based autonomous racing of 1:43 scale RC cars," OCAM 36(5), pp. 628–647, 2015 / arXiv:1711.07300 — https://arxiv.org/abs/1711.07300（**プレプリント無料**。MPCC の原典）

## 第40章 離散化とリアルタイム

**扱う階層**: 可変ステップ MIL → **固定ステップ MIL** → ソフトリアルタイム → ハードリアルタイム。この4段の性質の違いを1章で押さえる。

**扱わない**: 生成コードとの一致（第41章）、コード生成そのもの（第42章）、I/O を含む検証（第43章）。

**本文の骨子**
- **数値安定性で `h` を決める**：明示的ソルバの安定条件は系の最速時定数 `τ` に縛られる。前進オイラー（ode1）は概ね `h < 2τ`、RK4（ode4）は `h < 2.785τ`。
- **FSAE の最速時定数はタイヤ緩和 `τ = σ/V`**（第7章）。`V = 30 m/s`, `σ = 0.3 m` なら `τ = 0.01 s` → ode1 で `h < 0.02 s`、ode4 で `h < 0.028 s`。**`τ` は高速ほど小さくなるので、刻み幅の検証は必ず想定最高速で行う。低速のスキッドパッドで安定でも高速のオートクロスで発散する。**
- **マルチレート設計**：車両 1 ms／制御 10 ms／映像 16.7 ms（60 fps）／反力 1 kHz。単一サンプル時間で全部回すと実時間に入らない。**学生の実装で最も効く最適化の一つ。**
- **`v_x → 0` の特異点**：`α = atan(v_y/v_x)` は `v_x → 0` で特異。FSAE は発進・停止・極低速コーナーを必ず通るため、DIL では確実に踏む。NaN・数値振動の最頻出原因。対策は `v_x` の下限クリップか、緩和をスリップ角ではなく**タイヤ変形（deflection）ベース**で定式化すること。
- **ラップシムと DIL の本質的な違い**：ラップシム（QSS）は停止点を代数的に扱えるが、DIL は実時間で停止状態を連続的に通過しなければならない。

**限界と適用範囲節に書くこと**
- **可変ステップ ode45 で綺麗な応答が出たので「実装できる」と結論しない。** 可変ステップにはサンプル時間の概念が無く、実機で必ず生じる ZOH 遅れ・離散化位相遅れ・エイリアシングを構造的に見落とす。**可変ステップで安定な制御則が固定ステップ実装で発振するのは日常的。**
- `h` を精度だけで決めない。逆に `h` を詰めすぎると実時間予算を食い潰す。**この二律背反が本章の主題。**
- **剛性を人為的に下げる／減衰を足すのは常套手段だが、そうすると本来の共振周波数がずれる**（第22章の駆動系）。**駆動系振動の議論にはもはや使えなくなる**ことを必ず明記する。ここが「モデルをいつ信じてはいけないか」の核心的な例。
- Simscape の陰的ソルバの反復回数が可変だと TET が入力依存で変動する → **fixed-cost 化（局所ソルバ＋反復回数固定）が必須。**
- ソフトリアルタイム（Simulation Pacing / tic-toc）は汎用 OS 上で周期保証が無い。**これを根拠にラップタイムの絶対値を語ってはいけない。**
- **遅延吸収方式の無自覚が危険**：(a) `dt` をクランプするとシミュレーション時間が壁時計から遅れてスローモーション化し、**ドライバは「車が重い／レスポンスが鈍い」と誤認してセットアップ判断が汚染される**。(b) `dt` をそのまま伸ばすと積分精度が壊れる。

## 第43章 HIL（Hardware-in-the-Loop）

**扱う階層**: 実 ECU ＋ 実時間車両モデル ＋ 電気的 I/O。**故障注入**まで含めて初めて HIL。

**扱わない**: ドライバを入れる層（第44〜46章）、実車（第47〜48章）。

**本文の骨子**
- **FSAE では多くのチームで実行できない**と正直に書く。例外として、**電子スロットル（ETC）、APPS／BSE plausibility、シャットダウン回路**など安全系ロジックを内製するチームには、信号発生器＋実 ECU の簡易 HIL（マイコン2台構成でも可）が現実的な妥協点。**ここが FSAE で HIL が唯一現実的な価値を持つ領域。**
- 本教科書は ICE 対象なので、EV 部門で重視される高電圧安全系（AMS/IMD）の検証は範囲外と明記する。
- 構築するなら Simulink Real-Time ＋ Speedgoat I/O、dSPACE、NI VeriStand。簡易版は Simulink Desktop Real-Time ＋ 安価な DAQ、またはマイコン2台（一方が車両モデル、一方が被検 ECU）。

**限界と適用範囲節に書くこと**
- **HIL の車両モデルは実時間制約のために精度を落としてある。したがって制御ロジック・I/O・異常系の検証には使えても、車両挙動の予測には使えない。この混同が X-in-the-Loop 全体で最も高くつく誤解。**
- **センサ・アクチュエータの電気的模擬が不完全だと ECU の自己診断（DTC）が誤作動し、本題に入る前に止まる。実務では HIL 立ち上げ工数の大半がここに消える。学生チームが安易に手を出すとこの段で年度が終わる。**
- **故障注入（断線、地絡、電源短絡、センサ張り付き、CAN 喪失）を含めない HIL は、主目的である異常系検証を果たしておらず費用対効果が極めて悪い。**
- TET（タスク実行時間）を測っていなければオーバーランは静かに起きて結果を汚す。

## 第44章 DIL① モデル要件とレイテンシ

**扱う階層**: 固定ベース DIL のプラント要件と実時間予算。レイテンシの計測・整合・補償。

**扱わない**: 反力（第45章）、キューイング（第46章）、妥当性の定量化（第48章）。

**本文の骨子**
- **モデル要件の優先順位を FSAE 固有に決める**：13インチ級の小径タイヤ、平均 40〜60 km/h、低ダウンフォース。したがって DIL の忠実度はほぼ**タイヤモデルとサスペンションの質だけで決まり、空力モデルの粗さは相対的に問題にならない**。→ **「空力を削ってでもタイヤの緩和と非線形性を残す」**。
- `v_x → 0` 特異点対策（第40章）と、マルチレート設計（車両 1 ms／制御 10 ms／映像 60 fps／反力 1 kHz）。
- **レイテンシ予算**：視覚・運動・力覚の遅延を測り、揃え、必要なら予測で補償する。**不自然さと酔いを生むのは遅延の絶対値よりモダリティ間の相対的なズレ。**
- 実装経路：入力は `vrjoystick`（Simulink 3D Animation）または Joystick Input ブロック。3D 表示は Simulink 3D Animation ＋ Unreal Engine 連携、または VDB のシーン。ソフト実時間は `set_param(mdl,'EnablePacing','on','PacingRate','1')` ＋ `StopTime='inf'`。
- 予算感：固定ベース＋市販 FFB ホイール（Logitech / Thrustmaster / Fanatec）＋ペダル＋PC で概ね 10〜30 万円。**6DOF ヘキサポッドは学生予算外。**

**限界と適用範囲節に書くこと**
- **固定ベースでは横並進の知覚が欠落するため、横方向制御は絶対妥当性を持たない**（縦方向制御は絶対・相対とも良好、横方向は相対妥当性にとどまる、という実車比較の実証がある）。**絶対的なグリップ限界の評価、限界付近の主観評価を信じてはいけない。使ってよいのはセットアップの順位付けまで。**
- ソフト実時間の遅延吸収（第40章の (a)/(b)）がドライバの主観を汚染する。
- **市販ゲーム物理（Assetto Corsa 等）を自作モデルの検証基準にしない。** 物理は非公開でゲーム性のためにチューニングされている。ゲームは DIL の器としては有用だが、妥当性の根拠は必ず実車データに置く。

## 第45章 DIL② 反力とペダル

**扱う階層**: 第20章の反力トルクモデルを実時間で回し、FFB ホイールへ出力する層。ペダル（ブレーキ圧・剛性）。力覚レイテンシ。

**扱わない**: モーションキューイング（第46章）、妥当性評価（第48章）。

**本文の骨子**
- 反力の構成を第20章から引き継ぐ：`Mz`（トレール `t(α)` の減少込み）＋キャスタトレール×`Fy` ＋ KPI 由来のジャッキング ＋ コンプライアンス ＋ 摩擦。
- **MATLAB 経路の空白を正直に書く**：入力（舵角・ペダル）は `vrjoystick` や Joystick Input ブロックで読めるが、**FFB 反力の出力（トルク書き込み）には MATLAB/Simulink の標準経路が存在しない。** DirectInput/SDL への C MEX を自作するか、Unreal Engine / Unity 側で反力を扱うかの二択。**この「標準経路が無い」ことを隠さず書くのが誠実。**
- ペダル：ブレーキは踏力ではなく圧力／剛性感が支配的。実車のマスターシリンダ＋ロードセルを流用する経路も示す。

**限界と適用範囲節に書くこと**
- **反力を単なるセンタリングばね（線形）にすると、実車でドライバが限界を察知する最重要手がかり（セルフアライニングトルクのピークとその後の低下）が完全に消え、ドライバは限界を感じられず常にオーバードライブする。FFB ホイールを買っただけでは解決しない——反力の中身が本体。**
- **力覚の遅延を予算に入れない**と、ドライバの操舵と反力の位相が合わず操舵発振（human-in-the-loop oscillation）を起こす。視覚遅延ばかり議論して力覚を無視するのが典型的な失敗。
- 市販 FFB ホイールのトルク上限・帯域・内部フィルタが未知なので、**出力したトルク指令と実際に手に届くトルクは同じではない**。可能ならトルクセンサまたは既知の負荷で伝達特性を測る。

## 第46章 DIL③ キューイング

**扱う階層**: 古典 washout フィルタ（HPF ＋ チルトコーディネーション ＋ チルト速度リミッタ）。MPC ベースのキューイングは**位置づけのみ**。固定ベースでの代替キュー（シート傾斜、ベルトテンショナ、振動）。

**扱わない**: 6DOF ヘキサポッドの実装（実行不可能と明記）。

**本文の骨子**
- 古典 washout の構造と、なぜそれで「だませる」のか（前庭系の知覚閾値）。設計指針は classical / adaptive / optimal の分類に従う。
- **なぜ古典 washout では足りないか＝アクチュエータのストローク・速度限界を陽に扱えないから**。これが MPC キューイングの動機であり、**第39章の MPC と理論的に地続き**なので構成上の接続点として有用。
- **ヨー運動のフィードバックの重要性**は独立した論点として扱う価値がある（固定ベースでも一部再現の余地）。
- FSAE では 6DOF は予算外。**「知る価値はあるが実行しない」と明記する。**

**限界と適用範囲節に書くこと**
- **チルト角速度が知覚閾値を超えると「傾いている」と気づかれ、加速度の代替のはずが偽手がかり（false cue）に反転して逆効果になる。チルト速度リミッタは必須。**
- **washout の復帰運動そのものが誤った加速度を与える。**
- **スケーリングを 1 に近づけたくなるが、モーションストロークは常に足りないので必ずスケールダウンが必要。** 1 を目指すと確実にアクチュエータ限界に当たり、ハード的な頭打ちで不連続な手がかりが出る。
- パラメータが多く（各軸のカットオフ周波数、スケーリングゲイン、チルト速度リミット）、あるマニューバに合わせると別のマニューバで破綻する。
- MPC キューイングは予測が要るが、**実ドライバの操作は本質的に予測不能**（自動運転や既知コースでは有利、人間運転では不利）。また目的関数に埋め込む知覚モデル自体が不確かで、**客観最適が主観最良と一致する保証がない。**

## 第48章 実車データとの突き合わせ ★本書の閉じ方

**扱う階層**: 第26・27章の基準を**全モデル階層に適用する最終章**。相対妥当性の宣言、モデル仕様書の完成、階層を上げる／下げる判断の記録。

**扱わない**: 新しいモデル（この章では作らない）。

**本文の骨子**
- **突き合わせの手順を固定する**：時刻同期（`xcorr`）→ 区間分割 → 量ごとの残差 → 残差の系統性の読み方（オフセットか、勾配か、位相か）→ 原因候補への写像（オフセット＝`λμ`／幾何、勾配＝`Cα`／荷重感度、位相＝`σ`／`I_z`／レイテンシ）。
- **階層を上げる条件を再掲して締める**：(a) 今のモデルが破綻する現象を実測で確認した、かつ (b) 次の階層の係数を埋めるデータがある。**片方だけで上げてはならない。**
- **合わないときは、まずパラメータを疑う**（モデル階層を上げるのは最後）。
- 最終成果物は**モデル仕様書**：適用範囲（速度域・`a_y` 域・荷重域・温度域）、使った近似とその方向（楽観／保守）、較正した係数とその根拠、絶対値として主張する量と相対比較としてのみ主張する量、未確認事項の一覧。
- **DIL と実車の突き合わせ**：同一コースで実車テレメトリ（GPS/IMU/舵角/車速）と DIL ログを比較し、**relative validity（変化の方向と順位が一致すること）を示す**。absolute validity は主張しない。

**限界と適用範囲節に書くこと**
- **時間同期をせずに相関を取らない。** 数十 ms のズレで相関が崩れ、モデルが悪いのか同期が悪いのか判別不能になる。
- 総ラップタイムだけで合わせると2つの誤差が打ち消し合った状態を「相関が取れた」と誤認する。
- **DIL で速いセットアップが実車で速い保証は無く、実データで相関を確認するまでは仮説にすぎない。** ドライバの主観（「曲がりやすい」）と客観指標（ヨーレート応答、ラップタイム）は必ずしも相関しない。
- 検証データが1条件しかないなら、その条件でしか妥当性を主張できない。

**参照文献**
- Siegler, Deakin, Crolla, SAE 2000-01-3563, 2000 — https://doi.org/10.4271/2000-01-3563（有料）
- Godley, Triggs, Fildes, 2002 — https://doi.org/10.1016/S0001-4575(01)00056-2（有料。絶対／相対妥当性の切り分け）
- Monash Motorsport, "driversim" — https://www.monashmotorsport.com/blog/driversim（**無料**。relative validity のみを報告する実例）

## C. 現在の第2章の評価と改稿方針

### C.1 現状の評価

現在の第2章は `Fy = −Cα·α` を提示して `Cα` を「タイヤの特性値」と呼ぶところで止まっている。この構成には3つの実務上の欠陥がある。

**欠陥1：`Cα` がどこから来るのかが書かれていない。** 読者は `Cα` を「カタログから拾う数」または「TTC データから当てはめる数」としか理解できない。すると (a) TTC を持たないチームはこの章から先に進めず、(b) TTC を持つチームは第8〜9章で Magic Formula の係数を回すだけの作業者になる。**`Cα` が接地長・トレッド剛性・摩擦から出る数であることを知らないと、第10章の摩擦円も第20章のトレールも第13章の荷重感度も、すべて「そういうものだ」という暗記になる。**

**欠陥2：荷重依存が無い。** これが最も高くつく。第13章のロール剛性配分の中心命題（ロール剛性配分を前寄りにする→前軸横荷重移動増→荷重感度で前軸トータル横力減→アンダー）は、`Cα(Fz)` と `μ(Fz)` が頭打ちすることの上に完全に建っている。第2章で荷重依存を扱わないと、この因果連鎖の起点が本書のどこにも存在しないことになる。

**欠陥3：限界と適用範囲が「スリップ角が小さいとき」で終わっている。** 本書の実務水準の核は「いつ破綻するか」であり、破綻の**順序**（何が最初に効くか）を書かないと、読者は「どの問題に先に対処すべきか」を判断できない。

### C.2 改稿後の第2章の構成（節立てまで）

```
2.1 この章の問い
    「Fy = −Cα·α の Cα とは何か。どこから来て、いつ使えなくなるのか」

2.2 符号規約の宣言（本書で1度だけ）
    - 軸あたり K_f, K_r を正で定義し Fy = −K·α
    - 1輪あたり C を使う文献は K = 2C（安部の式に現れる係数2の正体）
    - 単位は rad 系（deg/g で書かれた文献は 57.3 倍ずれる。Gillespie は deg/g）
    - 章をまたいで混在させないという約束

2.3 線形タイヤモデル
    - Fy = −Cα·α と、そこに含まれる6つの仮定を列挙
      (1) |α| が微小（乾燥路レーシングタイヤで概ね |α| ≲ 2〜3 deg、
          ピークスリップ角の 1/3 程度まで）
      (2) Fz 一定  (3) キャンバ角ゼロまたは無視  (4) Fx = 0
      (5) 定常（過渡遅れなし）  (6) 摩擦限界に達しない
    - Mz = −Cα·α·t（t = ニューマチックトレール一定）＝仮定が1つ増える

2.4 Cα はどこから来るのか — ブラシモデルによる導出 ★新規
    - トレッドを剛体カーカス上の独立した弾性ブラシ毛の列と見なす
    - 仮定：接地圧が放物線分布／μ 一定／前端から粘着域・後端から滑り域の
      2領域構造／カーカスは剛／定常
    - 解析解から3つの結果が同時に出ることを示す：
        Cα = 2·cp·a²          （原点勾配 ＝ 線形モデルの Cα そのもの）
        Fy,max = μ·Fz          （摩擦飽和 ＝ 線形モデルには無い上限）
        t = a/3 から始まり α とともに単調減少しピーク付近でゼロへ
    - 「Cα は測る数ではなく、接地長 2a・トレッド剛性 cp・摩擦 μ から出る数」

2.5 荷重依存 — tire load sensitivity ★新規
    - 仮定 (2)「Fz 一定」だけを外す。Cα(Fz)、μ(Fz)
    - 物理的根拠：接地面積は荷重にほぼ比例して増えるが接地圧も上がり、
      ゴム摩擦が圧力に対して劣化するため μ は荷重とともに下がる

      荷重移動と荷重感度を入れたモデルは 37 km/h。約12%の過大評価

      （多項式外挿させない。FSAE は内輪 Fz≈0 まで抜けるので低荷重外挿を実際に踏む）

2.6 過渡の予告（定義は第7章） ★新規
    - タイヤ力はスリップ入力に瞬時には立ち上がらない。時定数は σ/V
    - 時間ではなく走行距離で決まるので、低速の FSAE では乗用車の高速走行時より
      遅れが時間として長く効く。「小さいタイヤだから過渡は速い」は誤り

2.7 データはどこから来るのか — TTC とその代替 ★新規
    - FSAE TTC：Calspan の平面ベルト試験機、FSAE の実走行速度に合わせた 25 mph、
```

### C.3 2.10「限界と適用範囲」に書く本文（破綻の順序）

1. **`|α|` がピークを越えると完全に破綻する。** 線形式は `α` とともに `Fy` が無限に増えるので、限界旋回・スピン・カウンターステアは原理的に表現できない。
2. **荷重移動を入れた瞬間に破綻する。** FSAE の車重・トレッド比では定常旋回で片輪荷重が2倍近く振れるため、誤差は数%ではなく**十数%オーダー**になる。→ 第13章。
3. **加減速中の旋回（トレイルブレーキング、コーナー脱出）では `Fx` が入り摩擦円が効くのでまったく合わない。** → 第10章。
4. **速いステア入力では緩和長による遅れでヨーレート位相が合わない。** → 第5章・第7章。
5. **ニューマチックトレールは限界付近で急減しゼロ・負にすらなるので、一定トレールの `Mz` では「限界の手応え抜け」が再現できない。** → 第20章（反力トルク）と第45章（DIL 反力）が根本から成立しなくなる。

**次の階層に進むべき条件**：この章の `Cα(Fz)` で第13章のロール剛性配分の定性的な向きが説明できるようになったら、定量精度が要る段階で第8章（Magic Formula）へ。ただし **`Cα(Fz)` を飛ばして Magic Formula に行くと、学生は荷重移動の物理を理解しないまま係数を回すだけになる。**
